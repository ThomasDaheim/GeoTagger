# GeoTagger Plan 4: Karte und Track-Liste – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GeoTagger zeigt rechts oben eine Leaflet-Karte mit den Dateien als gebündelte Marker und die geladenen GPX-Tracks. Koordinaten lassen sich auf der Karte setzen: per Drag & Drop aus der Liste, durch Verschieben eines Markers oder per Rechtsklick für die Auswahl. Rechts unten liegt die Track-Liste.

**Architecture:**
- **GeoHelper (`tf.geo`, `tf.geo.map`):** die Karte als wiederverwendbare Komponente `LeafletMapView`.
  - Sie ist aus GPXEditors `tf.gpx.edit.leafletmap` kopiert und entkoppelt: keine Preferences, kein `TrackMap`, kein Apache Commons.
  - Die Leaflet-Ressourcen liegen unter `/tf/geo/map/leaflet/`.
  - Eigenes JavaScript steckt in `GeoMap.js`: Marker nach ID, Cluster, Tracks, Umrechnung von Pixeln in Koordinaten.
  - JS ruft Java über das Objekt `jscallback` auf, wie in GPXEditor.
- **Marker-Abgleich in Java:** `LeafletMapView.showMarkers(alle)` vergleicht mit dem zuletzt gezeigten Stand (`MarkerDiff`) und schickt nur Änderungen ins JavaScript. Auch bei 3.000 Dateien kann GeoTagger so nach jeder Änderung einfach alle Marker übergeben.
- **GeoTagger:**
  - `MapPane` verbindet Karte und `MediaFile`: Marker, Auswahl, Kontextmenü und Drop.
  - `TrackListPane` zeigt die GPX-Dateien.
  - Der Controller verdrahtet beide mit Auswahl, Undo (`ChangeFieldsAction`) und `refreshFiles()`.

**Tech Stack:** Java 25, JavaFX 25.0.1 inkl. `javafx-web` und `jdk-jsobject`, Leaflet **1.8.0**, Leaflet.markercluster 1.4.1, leaflet-color-markers, JUnit 5.13.0, TestFX 4.0.18.

**Spec:** [2026-11-03-geotagger-design.md](../specs/2026-11-03-geotagger-design.md), Abschnitte „Umfang“ (Leaflet-Karte, Track-Liste), „Architektur / GeoHelper“ (`tf.geo.map`), „Hauptfenster“

## Global Constraints

- **Oberflächensprache: Englisch.** Gearbeitet wird direkt auf `master`, in GeoHelper und GeoTagger.
- **Lizenz-Header:** Jede `.java`-Datei beginnt mit dem BSD-Header aus GPXEditor (25 Zeilen, z. B. von `GeoTagger\src\main\java\tf\geotagger\model\Field.java`). Die Codeblöcke unten lassen ihn weg.
- **Javadoc:** Ist ein Kommentar vorhanden, dann vollständig (`@param`/`@return`/`@throws`), `<…>` steht in `{@code …}`.
- Compilerwarnungen in `src/main` und `src/test` werden behoben.
- **Versionen:** GeoHelper bleibt `tf.GeoHelper:GeoHelper:0.1` und wird per `gradlew build` (→ `publishToMavenLocal`) bereitgestellt.
- **Leaflet 1.8.0, nicht 1.9.4:** Mit 1.9.4 gab es Probleme, deshalb ist GPXEditor bewusst zurückgegangen („1.9.4 is not working with recent JavaFX versions (>= 20). Leads to flickering of tiles“, Commit `3914d29`). GeoHelper bleibt bei 1.8.0.
- **`JSObject`:** `netscape.javascript.JSObject` kommt aus `org.openjfx:jdk-jsobject` und braucht `--upgrade-module-path`, sonst nimmt javac das veraltete JDK-Modul („[removal]“-Warnung). Das Vorgehen ist dasselbe wie in GPXEditors `build.gradle` (Zeilen 195–231 und 306).
- **GeoHelper kennt GeoTagger nicht** (Spec). Alles mit `MediaFile` bleibt in GeoTagger.
- **Spec, Umfang Karte:**
  - Marker aller Dateien mit Koordinaten, gebündelt (Clustering).
  - Geladene Tracks werden angezeigt.
  - Koordinaten setzen per Drag & Drop aus der Liste, durch Verschieben eines Markers oder per Rechtsklick für die Auswahl.
- **Spec, Track-Liste:**
  - GPX-Dateien im Ordner (und in Unterordnern) werden automatisch aufgelistet.
  - Jeder Track lässt sich einzeln laden und auf der Karte ein- und ausblenden.
  - Weitere GPX-Dateien lassen sich hinzufügen.
  - Unlesbare GPX-Dateien werden als fehlerhaft markiert, die übrigen bleiben nutzbar.
- **Marker-Darstellung (Entscheidung dieses Plans):**
  - Gespeicherte Koordinaten: blau. Ungespeicherte Koordinaten: orange.
  - Ausgewählte Dateien: rot, **nicht** gebündelt, ziehbar und im Vordergrund.
  - Nur ausgewählte Marker lassen sich ziehen. So verschiebt ein versehentlicher Klick in einen Cluster nichts.

## Review Focus

1. **Aufrufe, bevor die Karte bereit ist:** Ein kleiner Ordner ist schneller geladen als die WebView. Marker und Tracks dürfen dann nicht verloren gehen. → `LeafletMapViewTest.callsBeforeReadyAreApplied` (Task 3)
2. **Dateinamen mit `'`, `"`, `\`, Umlauten oder `</script>`** als Marker-Titel dürfen das JavaScript nicht brechen. → `JsTest.escapesForJavaScript` (Task 1), `LeafletMapViewTest.titlesWithQuotesAreSafe` (Task 3)
3. **Ordner ohne Koordinaten bzw. mit genau einer Datei mit Koordinaten:** `fitBounds` mit leerer Liste lässt die Ansicht stehen, mit einem Punkt zentriert es. → `LeafletMapViewTest.fitBoundsWithoutPositionsKeepsTheView` (Task 3)
4. **GPX ohne Trackpunkte oder unlesbar:** markiert als fehlerhaft, keine Linie, die übrigen Tracks laufen weiter. → `GpxTrackTest.emptyTrackFails` (Task 7), `GeoTaggerTrackUiTest.unreadableGpxIsMarked` (Task 7)
5. **Auswahl einer Datei ohne Koordinaten** und Auswahl vieler Dateien: kein Schwenk, kein Fehler. → `GeoTaggerMapUiTest.selectingFileWithoutCoordinatesKeepsTheMap` (Task 5)

- [ ] **Step 2: `GeoMap.js` schreiben**

`$geo\src\main\resources\tf\geo\map\leaflet\GeoMap.js`. Es wird nach Leaflet, den Plugins und dem Anlegen von `myMap` ausgeführt.

```js
// GeoHelper: markers by id (clustered unless selected), tracks by id, pixel <-> lat/lng
var geoMarkers = {};
var geoCluster = L.markerClusterGroup({ chunkedLoading: true, spiderfyOnMaxZoom: true });
var geoSelected = L.layerGroup();
var geoTracks = {};
myMap.addLayer(geoCluster);
myMap.addLayer(geoSelected);

function geoRemoveMarker(id) {
    var marker = geoMarkers[id];
    if (marker) {
        geoCluster.removeLayer(marker);
        geoSelected.removeLayer(marker);
        delete geoMarkers[id];
    }
}

// list: [{id, lat, lng, title, icon, selected}] - replaces markers with the same id
function geoUpdateMarkers(list) {
    var clustered = [];
    for (var i = 0; i < list.length; i++) {
        var data = list[i];
        geoRemoveMarker(data.id);
        var marker = L.marker([data.lat, data.lng], { title: data.title, icon: window[data.icon],
            draggable: data.selected, zIndexOffset: data.selected ? 1000 : 0 });
        marker.geoId = data.id;
        marker.on('click', function (e) {
            jscallback.markerClicked(this.geoId, e.originalEvent ? e.originalEvent.shiftKey : false);
        });
        marker.on('dragend', function () {
            var position = this.getLatLng();
            jscallback.markerMoved(this.geoId, position.lat, position.lng);
        });
        geoMarkers[data.id] = marker;
        if (data.selected) {
            geoSelected.addLayer(marker);
        } else {
            clustered.push(marker);
        }
    }
    geoCluster.addLayers(clustered);
}

function geoRemoveMarkers(ids) {
    for (var i = 0; i < ids.length; i++) {
        geoRemoveMarker(ids[i]);
    }
}

function geoMarkerCount() { return Object.keys(geoMarkers).length; }
function geoClusteredCount() { return geoCluster.getLayers().length; }

function geoRemoveTrack(id) {
    if (geoTracks[id]) {
        myMap.removeLayer(geoTracks[id]);
        delete geoTracks[id];
    }
}

function geoShowTrack(id, coords, color) {
    geoRemoveTrack(id);
    geoTracks[id] = L.polyline(coords, { color: color, weight: 3, opacity: 0.8 }).addTo(myMap);
}

function geoSetTrackVisible(id, visible) {
    var track = geoTracks[id];
    if (!track) {
        return;
    }
    if (visible && !myMap.hasLayer(track)) {
        track.addTo(myMap);
    } else if (!visible) {
        myMap.removeLayer(track);
    }
}

function geoTrackCount() { return Object.keys(geoTracks).length; }
function geoVisibleTrackCount() {
    var count = 0;
    for (var id in geoTracks) {
        if (myMap.hasLayer(geoTracks[id])) {
            count++;
        }
    }
    return count;
}

function geoFitBounds(coords) {
    if (coords.length === 0) {
        return;
    }
```
